# CLI contract

This document defines PDFConcat's public command-line language. Changes to this grammar are product changes, not parser implementation details. The plan-file format has its own contract in [`PLAN.md`](PLAN.md).

## Grammar

```text
pdfconcat -o OUTPUT [option]... sequence-item...
pdfconcat [-o OUTPUT] [option]... --plan PLAN
pdfconcat --plan -                                  (plan on standard input)

sequence-item := PDF_PATH | --blank | --blank=TEXT
```

A sequence item's position is semantically significant: the place where `--blank` appears is the place where a generated blank page appears in the output.

Use the command line for short, hand-written jobs. For more than a few dozen files, or anything generated by a script or agent, use a plan file: operating systems cap the command line (about 32 KB on Windows, about 1 MB on macOS), and shells disagree about wildcard expansion (`cmd.exe` and PowerShell do not expand `*.pdf` for native programs at all).

## Options

| Option | Meaning |
| --- | --- |
| `-o FILE`, `--output FILE` | Destination PDF. Required unless the plan names an `output`; overrides the plan's `output`. |
| `--plan FILE` | Read the sequence from a [plan file](PLAN.md). `--plan -` reads the plan from standard input; relative paths then resolve against the working directory. Cannot be combined with sequence items. |
| `--overwrite` | Permit replacement of an existing output, only after the replacement has been assembled and verified. |
| `--dry-run` | Preflight inputs and report the interpreted assembly without creating output. |
| `--json` | Report the result (or dry run) as a single JSON document on standard output. |
| `--print-schema` | Print the JSON Schema of plan files and exit. |
| `-h`, `--help` | Print help and exit successfully. |
| `--version` | Print version, commit, and commit date and exit successfully. |

An option takes its value either as the next argument (`-o out.pdf`) or attached (`--output=out.pdf`). A value passed as a separate argument may not itself be a recognized option or sequence directive, so `-o --blank a.pdf` is an error rather than an output file named `--blank`. A value that begins with `-` (a negative offset, or text such as `-- draft --`) is passed in the attached form: `--blank-y=-36`. Unknown options are errors, and each option except the sequence directives may be given only once.

## Generated blank pages

`--blank` inserts one generated blank page. `--blank=TEXT` inserts one blank printing `TEXT`, overriding `--blank-text` for that page (`--blank=` prints nothing). The remaining `--blank-*` options set defaults for every blank in the run:

```text
--blank-size  --blank-background  --blank-text  --blank-font  --blank-font-size
--blank-color  --blank-anchor  --blank-x  --blank-y  --blank-width
--blank-align  --blank-leading
```

Their values, defaults, layering with plan settings, text placement, and the supported character set are specified in [`BLANK_PAGES.md`](BLANK_PAGES.md). Passing `--blank-*` options when the sequence contains no blank is an error.

## Sequence directives and paths

```text
pdfconcat -o out.pdf a.pdf --blank b.pdf       blank between documents
pdfconcat -o out.pdf --blank a.pdf b.pdf       leading blank
pdfconcat -o out.pdf a.pdf b.pdf --blank       trailing blank
pdfconcat -o out.pdf a.pdf --blank --blank b.pdf
pdfconcat -o out.pdf a.pdf --blank=Appendix b.pdf
```

`--` ends option and directive parsing: every later argument is a literal PDF path, so `--blank` after `--` is a file named `--blank`. A relative path beginning with `-` can also be written `./-name.pdf`. A lone `-` is a path, not standard input.

PDFConcat never expands wildcards. If a missing input contains `*`, `?`, or `[`, the error says so.

A PDF path may appear more than once; each occurrence is assembled again at that position.

## Output policy

The output path is mandatory, from `-o` or the plan. PDFConcat never invents a timestamped or directory-derived output name.

An existing regular-file output is an error unless `--overwrite` is present. The output may not refer to any source PDF or to the plan file, even with `--overwrite`. Existing symbolic-link outputs are refused. The output directory must already exist.

## Validation and error reporting

All source PDFs are validated before assembly, concurrently. Failures are collected rather than stopping at the first: the error reports how many inputs failed and lists the first 20, so a thousand-file job is fixed in one pass. Blank styles are checked before any PDF is read.

## Dry-run semantics

A dry run resolves the sequence, checks every distinct input exists and is a regular file, validates each PDF, reads each page count and size, resolves every blank's size and style, and prints the interpreted assembly: each part's output page range, the document or blank description, and the expected total. It performs no assembly or publication. With `--json` the same information is emitted as JSON (`parts` is present only for dry runs).

## Streams and progress

Dry-run plans, success reports, `--help`, `--version`, and `--print-schema` go to stdout. Errors and warnings go to stderr. When stderr is an interactive terminal, a single self-erasing progress line shows PDF validation; it never appears in redirected output.

## Exit status

| Status | Meaning |
| ---: | --- |
| `0` | Success, including `--help`, `--version`, `--print-schema`, and a successful dry run. |
| `1` | Operational failure: unreadable or invalid plan, filesystem, PDF validation/assembly, verification, or publication. |
| `2` | Usage error: malformed command line, or a missing output. |
