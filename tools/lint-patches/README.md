# Source attribution and semantic field use

The development linter is built from the exact upstream module and reviewed patch pinned in `tools/versions.env`. Install it with `go run ./tools/installtools golangci-lint`.

Upstream depguard selects file rules using compiler-adjusted `//line` filenames. Upstream gosec can also attach a diagnostic to an adjusted line of the physical file, allowing an unrelated source line to satisfy a diagnostic exclusion. The patch makes the linter's two Go parsing paths retain physical filenames, lines and columns. Original source and compiler directives remain unchanged. All token positions retain shared file-set ranges, including concurrent parsing and lazy export-data additions.

The installer verifies the module zip, module checksums, source tag epoch, and patch digest, generates temporary vendored dependencies from the verified unchanged graph, applies the combined source-contract patch, runs the physical parser and semantic graph race tests where the Go toolchain supports them (ordinary tests on Windows ARM64), and builds with the upstream dependency graph. It requires `go.mod` and `go.sum` to remain byte-identical before and after patching, dependency verification, helper tests, and compilation. Build metadata uses the stable upstream version plus `source-contracts.<patch SHA-256>`; the commit field is explicitly `patch-sha256:<digest>`, and the date field is explicitly `upstream-source:<tag time>`. The distinct version segregates cached diagnostics. These fields establish build identity, not review quality or a VCS commit.

`qualitygate architecture` proves mapped filenames cannot escape import ownership; `qualitygate lint-config` proves physical diagnostic predicates under valid directives, including warm-cache runs and an unrelated-source exclusion negative control. Syntax-error positions are normalized through their physical offsets.

Golangci-lint's upstream source is GPL-3.0; this patch modifies that development tool under the same license. The verified upstream GPL license is included in [LICENSE](LICENSE); the installer also retains it in its temporary source tree. The physical-position helper retains that GPL license; the honnef graph changes retain their upstream MIT license. The patch includes the modified source and its tests; the base source is identified by its verified module version and checksums.

Source builds require the Go toolchain declared in `go.mod`, Git, and a C compiler for supported race-detector targets. Windows ARM64 runs ordinary helper tests because its Go SDK has no race detector; that is reported as unavailable race instrumentation. The development linter and its GPL source material are separate from PDFConcat runtime dependencies and are excluded from product archives.

The operation-linked `honnef.co/go/tools v0.8.1` unused graph patch follows actual concrete map-key/equality operations through nonblank value structs and positive arrays. It preserves dead-owner reachability, pointer/interface boundaries, and strict unread-field diagnostics. It does not infer fields hidden by generic callees or interface-erasing helpers. The modified dependency retains its MIT license in [honnef-LICENSE](honnef-LICENSE); vendored files are temporary build inputs, not product archives. No field-write exemption or diagnostic postfilter is used.
