# Mutation execution

The development mutation tool is built from the verified upstream Gremlins module with the reviewed executor patch. Its authoritative module/archive/checksum/source-time and patch pins are in [tools/versions.env](../versions.env). Install it with `go run ./tools/installtools gremlins`; run the project campaign with `go run ./tools/qualitygate mutation`.

The installer downloads the official Go module archive through the public module proxy and checksum database, verifies the pinned ZIP SHA-256, module and `go.mod` sums, and source-tag epoch, then applies the digest-checked `gremlins-executor.patch` with Git in an isolated directory. Upstream `go.mod` and `go.sum` must remain byte-identical after patch application, dependency download and verification, mandatory controls, and compilation. Ambient workspaces and private checksum exclusions are disabled; `GOTOOLCHAIN=local` uses the project's declared Go toolchain. Fresh source installation requires access to the public proxy and checksum database.

Mandatory installer tests cover the command, execution, coverage, engine, worker-pool, work-directory and report packages, including worker judgment, shared AST restoration after failed writes, apply/rollback, cancellation, actual pool size, and descriptor closure with garbage collection disabled. They use the Go race detector where supported; Windows/arm64 uses ordinary tests because its SDK has no race detector. Setup requires Go, Git and a C compiler on race-supported targets. The installer does not add dependencies to PDFConcat's runtime module graph.

The binary version is the upstream version plus `executor.<full patch SHA-256>`. The installer and mutation gate check the exact native printed version/target and independently inspect Go build metadata for the upstream module, command package and host GOOS/GOARCH. A source build's `(devel)` module version is not evidence of an official tagged binary. Gremlins supplies only the `main.version` linker symbol; no commit or build-time field is invented. The source-tag epoch identifies upstream source provenance, not the actual compilation time. A failed build or identity check leaves an existing owned tool binary untouched.

The patch keeps all discovered host mutants executable, including those the coverage dry run labels `NOT COVERED`. Original discovery status remains separate from execution judgment. Counts precede ratios; resolved outcomes (killed, lived and not viable) are measured against all reported outcomes, with efficacy unavailable when its denominator is zero. The JSON `mutations_coverage` field is phase-specific: dry-run statement mapping or the full report's resolved fraction. It does not prove native Go coverage or campaign completion. The project gate compares the complete discovered identity set with the final report and rejects a final uncovered judgment. Compiler position directives cannot change physical mutation locations.

Go test JSON is retained and classified with process outcome and diagnostic evidence. Named test failures and supported panic evidence can kill a mutant; an attributable source compilation failure is not viable. Missing or incomplete execution evidence, unknown process failures, infrastructure/resource failures and artifact failures remain errors. Go can repeat a failed parent event before or after its panic text. Only an identical repeated named FAIL may be deferred until the full stream settles, and it requires that same package's terminal failure, panic header, stack and Go exit 1. Other duplicates and unsettled panic evidence remain errors; stack exhaustion remains a resource error. A surviving mutation must match the successful baseline's package and top-level test census. Dynamic subtests remain visible without freezing their runtime-generated names into that census. Baseline and mutant commands use `-count=1` to execute tests rather than replay cached results. This is required because a test that builds a child executable can depend on source files absent from its own test-binary dependency graph; Go can otherwise replay a passing test after only the child source changes. The compiled Go build cache remains enabled. An ERROR judgment still fails the campaign. A worker may execute the next mutant only after process, cache, raw-output and receipt ownership have settled and mandatory source rollback succeeds. Apply, rollback or unsettled ownership failures invalidate the worker and refuse later execution; judgment uncertainty alone does not establish a damaged worker tree.

The gate retains discovery and campaign JSON plus adjacent `.executions` directories. Baseline and per-mutant raw stdout JSON, stderr, result records and cache receipts are retained. Per-mutant `execution_reference` binds the physical mutation identity to its result and raw-output digests; discovery status, execution status, timestamps and failures remain distinguishable. Existing evidence paths are rejected instead of overwritten. Digests prove artifact identity and integrity, not review quality.

The project controller exposes actual execution workers (1 through 4) and translates integration counts to the pinned upstream pool input. Its optional `-max-duration` budget is charged from command entry, with 60 seconds reserved for cleanup. Discovery and campaign receive the remaining work time through the tool's internal deadline. POSIX cancellation forwards Interrupt, with Go's 45-second `Cmd.WaitDelay` backstop inside that reserve, leaving 15 seconds for final controller cleanup and receipts. This is a process-management budget, not an absolute guarantee against delayed kernel or filesystem operations. Windows Interrupt forwarding is unsupported; budget expiry uses the portable internal deadline, and native parent-cancellation rollback/cleanup remains a verification prerequisite. A default duration of zero imposes no optional total deadline.

Raw stdout and stderr have a combined 32 MiB limit per Go command. Mutation workers share a 2 GiB campaign output budget, including both package checks and whole-module commands. Download and baseline coverage commands each have a separate 32 MiB allowance in both discovery and execution. This caps their combined raw output plus mutation output at 2.125 GiB per partition, excluding logs and other files. The 2 GiB partition allowance is about 2.6 times the largest retained complete native partition output (824,066,365 bytes); the per-command limit separately stops a single noisy process. These observations justify headroom, not a prediction of future output. Both native process implementations copy owned pipes through the budget before writing retained files. Exhaustion terminates and joins the owned process tree, retains the exact partial prefix and its digest, and reports an execution error; truncated evidence cannot pass. Metadata, coverage profiles, build scratch and files written directly by tests are outside these output budgets. A filesystem quota is required for a strict total disk ceiling.

Go commands own their process lifecycle: POSIX workers use process-group cleanup before the parent is reaped; successful group SIGKILL also waits for terminal membership rather than assuming the syscall return proves settlement. Linux checks stable owned `/proc` terminal observations. Windows creates the process suspended, assigns it to a private Job Object, installs explicit standard handles and resumes it. Job termination is asynchronous: job draining, retained-process signaling and pipe joining share one five-second cleanup wait allowance. Cancellation and cleanup failures remain visible. Darwin permission-denied process-group checks share the five-second cleanup deadline established by the first group signal. Only known kernel exit transitions (`P_WEXIT`) may be polled, and cleanup succeeds only after every remaining member is an owned zombie with the unreaped leader identity preserved. Unknown or genuinely live members remain errors. Pipe draining uses that same deadline, which cancellation and EOF never reset. Scratch cleanup retains a native file identity lease, opens and verifies a confining SDK root after producers stop, and then uses rooted removal and can restore the task's own restrictive directory permissions (including modes 000 and 0500); it does not repair outside files or symlinks. Cross-compiling the Windows controls proves compilation only: native Windows execution remains a release prerequisite, including the owned-handle and descendant-cleanup controls.

Baseline and mutant commands both use `-cover`: Go 1.27 can report an empty package as PASS when instrumented and SKIP otherwise. A compiled positive/negative control checks matching instrumentation and rejects altered or missing named tests; the successful census is not relaxed. Coverage-parser syntax diagnostics use the SDK's timestamped repeated-source wrapper; attribution requires matching owned filenames and a numeric source location. Physical root/source containment accepts native directory aliases while rejecting escaped symlinks, missing/nonregular files, mismatched wrappers and resource failures. The native retained-receipt control exercises actual covered compilation.

Baseline/download execution and each mutation worker also own a stable temporary directory for `GOTMPDIR`, `TMPDIR`, `TMP` and `TEMP`, outside the campaign workspace. Settled commands clear its contents before reuse; final cleanup removes the root. Uncertain descendant or cleanup ownership retains temporary files, build caches and source workspaces with their exact paths, skips further execution and refuses approval. Inner cache/source cleanup refusals also prevent ancestor workspace removal, preserving an unknown substituted directory. A failed SDK without a readable terminal ownership report also causes the controller to retain its source snapshot.

Baseline/download execution and mutation workers use exclusive temporary Go build caches. The global cache is never cleaned. `GOCACHE` is overridden and ambient `GOCACHEPROG` is explicitly cleared so an external cache program cannot redirect ownership. Cleanup deletes only lease-verified task-owned temporary caches; receipts retain final logical sizes. After each command, cache receipts record logical bytes; a cache exceeding the private 4 GiB trigger is trimmed by removing older cache files through the verified owned directory handle until it is within the trigger, preserving newer entries. This is a post-command trim trigger with one-command growth overshoot, not a strict disk or RAM ceiling. Directory identity, symlink/nonregular entries, inspection failures, failed trimming and cleanup errors are checked rather than treated as successful judgments. The cache policy does not truncate the discovered mutant set or reduce required tests.

The project validates every registry source reference against the clean snapshot before discovery or tool lookup. Repository-instance anchor freshness belongs to this preflight, rather than to tests of intentionally mutated inputs; unit rejection controls for the registry remain mandatory. Snapshot copying rejects listed symlinks and nonregular files, checks every present owned Go input through the existing inventory, and checks native `EmbedFiles`, `TestEmbedFiles` and `XTestEmbedFiles` through Go's package discovery. Deleted tracked files stay deleted. Ignored arbitrary dynamically read test/config fixtures must be tracked or unignored; they cannot be inferred from compiler metadata.

The hosted workflow partitions every native runtime source across the disjoint jobs per host declared in the [campaign matrix](../../.github/workflows/campaigns.yml), each with two workers and a five-and-a-half-hour work budget. The earlier two-hour whole-corpus run judged about 600 of over 6,400 Linux mutants in an hour; its limit could not establish completion. Source files are assigned in descending byte size to the least-loaded partition, with stable path and partition-index tie breaks. The estimate comes from frozen source bytes, while independent discovery still proves the complete mutant inventory. Source size does not predict test execution time, so equal byte counts do not guarantee equal completion times. Every partition retains whole-suite integration judging. Full pristine source inventories, SHA-256 identities and selected files are retained next to each report; CI requires every partition, and incomplete or failed partitions refuse approval. Plan an explicitly authorized campaign budget from measured host baselines and retained completion evidence; measure the native whole-baseline timing on each target before choosing a campaign budget. Do not treat a timed budget's partial report as a completed pass. Integration first runs the affected package alone when its baseline has named tests. A fully judged package failure settles that mutation without building later packages. A package survivor proceeds to the whole-module command with `-p 1 -failfast`, testing the affected package before `./...`. Both stages share the original per-mutation deadline; there is no retry or renewed time budget. Successful package-check stdout, stderr, result and cache receipts are retained under `<mutation-digest>.package/`; the canonical receipt describes the terminal package failure or the whole-module result. Evidence-directory collisions and archive failures refuse worker reuse. The affected import identity comes from the physical source-directory metadata, module root and calling directory, including nested `main` packages. Absolute directory aliases resolve consistently; normal campaign source ownership remains with the frozen snapshot and apply boundary. Integration priority, debugger scope and successful test-census lookup use that same identity. Real package-execution controls prove that a named failure does not build an unrelated malformed package, later-package failures are still detected, both stages retain the same deadline, and prior evidence cannot be overwritten. Successful whole-module commands execute every baseline package/test exactly once; package deduplication belongs to Go. It retains exact successful top-level census validation for survivors; dynamic subtests remain visible but are not frozen into that census.


Windows directory identity leases explicitly share deletion so verification does not prevent owned
cleanup or native substitution controls. The SDK root is opened and identity-checked at cleanup,
after producer joining, rather than pinning the worker namespace throughout execution. Windows
permission rejection tests install an effective-only, protected current-user deny/allow DACL
on each owned directory and independently prove the denied operation. They restore the original DACL
and inheritance state. A locked thread uses a private token with privileges disabled so enabled
backup/restore privileges cannot bypass its denial; prior thread identity is restored. Inherited
runner permissions are not merged into the denial fixture; POSIX chmod assumptions and creator-owner placeholder ACEs are not a Windows oracle.
Missing-command controls preserve the actual native lookup/start cause. A missing launch in a test
is diagnosed before inspecting command fields. These changes require native Windows execution,
separately from cross-compilation.

The mutation controller derives exclusions from the complete physical owned-source inventory
against Go's compiled runtime inventory. This includes an entire native test-support directory
when Go omits it on the host, while every compiled runtime source remains selected. The native
installer tests use owned portable temporary roots rather than a POSIX-only `/tmp` stub.
