# Mutation execution

The development mutation tool is built from the verified upstream Gremlins module with the reviewed executor patch. Its authoritative module/archive/checksum/source-time and patch pins are in [tools/versions.env](../versions.env). Install it with `go run ./tools/installtools gremlins`; run the project campaign with `go run ./tools/qualitygate mutation`.

The installer downloads the official Go module archive through the public module proxy and checksum database, verifies the pinned ZIP SHA-256, module and `go.mod` sums, and source-tag epoch, then applies the digest-checked `gremlins-executor.patch` with Git in an isolated directory. Upstream `go.mod` and `go.sum` must remain byte-identical after patch application, dependency download and verification, mandatory controls, and compilation. Ambient workspaces and private checksum exclusions are disabled; `GOTOOLCHAIN=local` uses the project's declared Go toolchain. Fresh source installation requires access to the public proxy and checksum database.

Mandatory installer tests cover the execution, coverage, engine, worker-pool, work-directory and report packages, including worker judgment, apply/rollback, cancellation, actual pool size, and descriptor closure with garbage collection disabled. They use the Go race detector where supported; Windows/arm64 uses ordinary tests because its SDK has no race detector. Setup requires Go, Git and a C compiler on race-supported targets. The installer does not add dependencies to PDFConcat's runtime module graph.

The binary version is the upstream version plus `executor.<full patch SHA-256>`. The installer and mutation gate check the exact native printed version/target and independently inspect Go build metadata for the upstream module, command package and host GOOS/GOARCH. A source build's `(devel)` module version is not evidence of an official tagged binary. Gremlins supplies only the `main.version` linker symbol; no commit or build-time field is invented. The source-tag epoch identifies upstream source provenance, not the actual compilation time. A failed build or identity check leaves an existing owned tool binary untouched.

The patch keeps all discovered host mutants executable, including those the coverage dry run labels `NOT COVERED`. Original discovery status remains separate from execution judgment. Counts precede ratios; resolved outcomes (killed, lived and not viable) are measured against all reported outcomes, with efficacy unavailable when its denominator is zero. The JSON `mutations_coverage` field is phase-specific: dry-run statement mapping or the full report's resolved fraction. It does not prove native Go coverage or campaign completion. The project gate compares the complete discovered identity set with the final report and rejects a final uncovered judgment. Compiler position directives cannot change physical mutation locations.

Go test JSON is retained and classified with process outcome and diagnostic evidence. Named test failures and supported panic evidence can kill a mutant; an attributable source compilation failure is not viable. Missing or incomplete execution evidence, unknown process failures, infrastructure/resource failures and artifact failures remain errors. A surviving mutation must match the successful baseline's package and top-level test census. Dynamic subtests remain visible without freezing their runtime-generated names into that census. Actual source/input-keyed Go test caching remains enabled, so named events can be cached replay; the tool does not claim `-count=1` execution.

The gate retains discovery and campaign JSON plus adjacent `.executions` directories. Baseline and per-mutant raw stdout JSON, stderr, result records and cache receipts are retained. Per-mutant `execution_reference` binds the physical mutation identity to its result and raw-output digests; discovery status, execution status, timestamps and failures remain distinguishable. Existing evidence paths are rejected instead of overwritten. Digests prove artifact identity and integrity, not review quality.

The project controller exposes actual execution workers (1 through 4) and translates integration counts to the pinned upstream pool input. Its optional `-max-duration` budget is charged from command entry, with 60 seconds reserved for cleanup. Discovery and campaign receive the remaining work time through the tool's internal deadline. POSIX cancellation forwards Interrupt, with Go's 45-second `Cmd.WaitDelay` backstop inside that reserve, leaving 15 seconds for final controller cleanup and receipts. This is a process-management budget, not an absolute guarantee against delayed kernel or filesystem operations. Windows Interrupt forwarding is unsupported; budget expiry uses the portable internal deadline, and native parent-cancellation rollback/cleanup remains a verification prerequisite. A default duration of zero imposes no optional total deadline.

Go commands own their process lifecycle: POSIX workers use process-group cleanup before the parent is reaped; Windows creates the process suspended, assigns it to a private Job Object, installs explicit standard handles and resumes it. Cancellation and cleanup failures remain visible. Darwin permission-denied process-group checks share the five-second cleanup deadline established by the first group signal. Only known kernel exit transitions (`P_WEXIT`) may be polled, and cleanup succeeds only after every remaining member is an owned zombie with the unreaped leader identity preserved. Unknown or genuinely live members remain errors. Pipe draining uses that same deadline, which cancellation and EOF never reset. Scratch cleanup uses retained SDK root/file ownership and can restore the task's own restrictive directory permissions (including modes 000 and 0500); it does not repair outside files or symlinks. Cross-compiling the Windows controls proves compilation only: native Windows execution remains a release prerequisite, including the owned-handle and descendant-cleanup controls.

Baseline/download execution and mutation workers use exclusive temporary Go build caches. The global cache is never cleaned. `GOCACHE` is overridden and ambient `GOCACHEPROG` is explicitly cleared so an external cache program cannot redirect ownership. Cleanup deletes only lease-verified task-owned temporary caches; receipts retain final logical sizes. After each command, cache receipts record logical bytes; a cache exceeding the private 4 GiB trigger is trimmed through `go clean -cache` configured for that same owned directory. This is a post-command trim trigger with one-command growth overshoot, not a strict disk or RAM ceiling. Directory identity, symlink/nonregular entries, inspection failures, failed trimming and cleanup errors are checked rather than treated as successful judgments. The cache policy does not truncate the discovered mutant set or reduce required tests.

The project validates every registry source reference against the clean snapshot before discovery or tool lookup. Repository-instance anchor freshness belongs to this preflight and `lint-config`, rather than to tests of intentionally mutated inputs; unit rejection controls for the registry remain mandatory. Snapshot copying rejects listed symlinks and nonregular files, checks every present owned Go input through the existing inventory, and checks native `EmbedFiles`, `TestEmbedFiles` and `XTestEmbedFiles` through Go's package discovery. Deleted tracked files stay deleted. Ignored arbitrary dynamically read test/config fixtures must be tracked or unignored; they cannot be inferred from compiler metadata.

The hosted workflow's two-hour/two-worker budget is a configured limit, not evidence that every host can finish the corpus. Plan an explicitly authorized campaign budget from measured host baselines and retained completion evidence; measure the native whole-baseline timing on each target before choosing a campaign budget. Do not treat a timed budget's partial report as a completed pass. Full integration uses first-failure judging (`-failfast`), with exact successful top-level census validation for survivors; dynamic subtests remain visible but are not frozen into that census.
